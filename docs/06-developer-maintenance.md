# Что требует разработчика

Бот задуман как daemon: при живых кредитах X и заполненной очереди он постит сам. Ниже — работы, которые **нельзя** закрыть «кнопкой в админке» (админки нет).

## Заказчик / оператор может сам

| Задача | Как часто | Кто |
|---|---|---|
| Пополнить кредиты X API при `402 credits depleted` | По факту исчерпания (сейчас это **блокер**: с 27.08.2026) | Владелец Developer Portal |
| Проверить, что посты выходят в X | 1–2 раза в неделю | SMM / заказчик |
| Пополнить баланс DeepSeek | Редко (квалификация дешёвая относительно X) | Владелец platform.deepseek.com |
| Прочитать лог «жив / очередь пуста / ошибка» | По инциденту | Любой с SSH, по инструкции из [05-vps-deploy.md](05-vps-deploy.md) |

## Нужен разработчик

| Задача | Типичная частота | Комментарий |
|---|---|---|
| Сменить parent-твит (`--tweet-id` в compose + rebuild) | Раз в кампанию / когда вирусный пост выгорел | Сейчас discovery по `2079647800636428422` помечен done, очередь пуста — без нового твита или сброса флага бот крутит холостые циклы |
| Сброс `discovery_complete` / курсора слайсов, чтобы добрать новые ответы под **тем же** постом | По мере надобности | Правка SQLite meta, см. [04-database.md](04-database.md) |
| Текст outreach, стоп-слова, geo, промпт DeepSeek | Раз в 1–3 месяца или по жалобам на качество | Правка Python + rebuild образа |
| Видеофайл | При смене креатива | Положить mp4, rebuild; сбросить `video_media_id` в meta |
| Лимит `DAILY_POST_LIMIT`, jitter | Редко | `.env` + recreate контейнера, чтобы подхватил env |
| 403 «account is not permitted» на видео | По инциденту | Права приложения X + возможный фикс upload |
| Утечка / ротация ключей после gitleaks | Разово при handover, далее при компрометации | См. [07-keys-and-access.md](07-keys-and-access.md) |
| Search-бот вместо / вместе с reply | Разово, продуктовое решение | Сейчас остановлен; два бота с одного аккаунта делят лимиты |
| Переезд на отдельный VPS | Разово при передаче | Текущий сервер **общий** с RAG/Qdrant |
| Docker/диск/после ребута не поднялся контейнер | Редко | `restart: unless-stopped` обычно достаточно |
| X сменил API (search/all, media v2) | Непредсказуемо | Переписывать клиент |

Оценка нагрузки после стабилизации: **0–2 часа в месяц** при живых кредитах и актуальном parent-твите. Пики — смена кампании (новый tweet-id, прогон discovery) и разбор 402/403.

## Что разработчик делает при типовых инцидентах

**Очередь пуста, discovery=done, постов нет.**  
Либо кредиты X кончились, либо твит «вычерпан». Решение: биллинг X и/или новый `--tweet-id`, либо сброс `discovery_complete`.

**В логе 402.**  
Не рестартить контейнер. Пополнить кредиты. Failed-лиды сами в очередь не вернутся.

**В логе 403 not permitted.**  
Проверить App permissions (Read+Write, media). Бот ставит паузу 5 часов и ретраит лид.

**Контейнер Exited 137.**  
Это SIGKILL (OOM или `docker kill`). Search-бот так умер 08.07.2026. Смотреть `dmesg` / `docker inspect`. Reply-бот с 30.07 не падал.

**Хотят «другой текст каждому».**  
Сейчас текст константа. Нужна доработка: генерация в DeepSeek + антидубль, иначе X режет duplicate content.

## Чего разработчик не должен делать «на всякий случай»

- `docker compose up -d` без `reply-bot`
- `scripts/reset_vps_db.py --yes`
- `--deploy-db` в `sync_to_vps.py` на живую прод-БД
- Рестарт reply-бота ради просмотра логов (`docker logs` достаточно)
- Любые команды вне `/opt/movetorussia/twitter_agent`
