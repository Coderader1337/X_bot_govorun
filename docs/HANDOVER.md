## Рекомендуемый порядок сдачи

Согласованный вариант: закрытая репа, ключи API не жжём, историю не тащим, пароль VPS меняем.

1. Собрать чистый снимок файлов (без `.git`, `.env`, `venv/`, `data/`, `logs/`). Проверить, что в дереве нет паролей (`scripts/sync_to_vps.py` уже читает env).
2. `git init` в этой копии → первый commit → новый **private** remote на аккаунте/орге заказчика → `git push -u origin master`. Не `remote set-url` на текущий репозиторий.
3. Передать `.env` **вне git** (менеджер паролей / шифрованный канал). Шаблон — `.env.example`.
4. Созвон: заказчик входит в developer.x.com и platform.deepseek.com. Биллинг X — пополнить (`402` с 27.08.2026).
5. Сменить пароль root VPS, обновить `VPS_PASS` в локальном `.env` и в `/opt/movetorussia/.env` (его читают другие проекты на той же машине). Контейнер reply-бота не рестартовать ради этого.
6. Решить доступ к серверу: отдельный VPS под бот **или** unix-пользователь только на `twitter_agent`. Root общего сервера заказчику не отдавать.
7. Удалить или архивировать старый GitHub `Coderader1337/twitter_agent` (не делать public).
8. Совместный прогон по [01-setup-from-scratch.md](01-setup-from-scratch.md): `--once --dry-run`, затем живой цикл после кредитов.
9. На общем VPS не делать `docker compose down` / не стартовать `twitter-bot`.
